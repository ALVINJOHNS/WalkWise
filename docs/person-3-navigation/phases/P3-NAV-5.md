- Agreed and implemented wrapper: `POST /api/route` accepts `{ "venue_id": "...", "start_node_id": "...", "destination_feature_id": "..." }`; it resolves the latest published immutable snapshot for the venue, reads the selected feature's explicit `access_node_id`, and passes the snapshot graph into `find_route`. The response includes venue/event/version identity and the route result. Missing venue/snapshot returns 404; malformed or unknown references return field-specific 400; valid unreachable or invalid-length routes return HTTP 200 with `ok:false`. Visitor requests do not route against mutable drafts. Person 4 owns wrapper, serializer, snapshot selection, and page wiring; Person 3 owns only pure routing helpers. Contract alignment is recorded from the implementation, P4-INT-6, and shared contract; no separate live peer sign-off was available in this review.
